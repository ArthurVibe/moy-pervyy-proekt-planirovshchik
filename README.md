# What's Up, Bro?

Персональный браузерный планировщик по [ТЗ v1.2](tz.md). Локальная реализация завершена; полная приёмка на целевых платформах и оценка удобства ещё открыты. История работы — в [plan.md](plan.md).

## Приложение и запуск

Приложение состоит ровно из `prototype/index.html`, `prototype/style.css` и `prototype/script.js`. Сборка, npm, серверная логика и база данных не нужны. Документация и `tests/` не входят в каталог публикации.

Основной пользовательский запуск — постоянный HTTPS-адрес статического размещения содержимого `prototype/`. На 18.10.2026 адрес не предоставлен, публикация не выполнялась. Подходят Cloudflare Pages или другой статический HTTPS-хостинг: каталог публикации `prototype/`, без команды сборки. Размещение выполняется отдельно.

Для разработки на своей машине из корня проекта запустите статический сервер:

```sh
python -m http.server 8765 --bind 127.0.0.1 --directory prototype
```

В Windows при необходимости используйте `py` вместо `python`. Откройте локальный адрес этого сервера на той же машине, порт 8765. Сервер только раздаёт файлы; задачи в него не отправляются. Сервер в облачной среде не является внешним предпросмотром для пользователя.

Открытие `prototype/index.html` двойным щелчком — дополнительный режим `file://`, без гарантии одинакового хранения в браузерах. В установленном облачном Chromium он заблокирован управляемой политикой (`ERR_BLOCKED_BY_ADMINISTRATOR`), поэтому не проверен. Открытие из iOS Files не является поддержанным основным способом.

## Что можно делать

- Создавать задачи с названием до 200 Unicode-символов, необязательной датой и временем; дата остаётся для следующего ввода, название и время очищаются.
- Редактировать, переносить срок, отменять правку; завершать задачи, возвращать в работу и удалять с подтверждением.
- Видеть группы «Просрочено», «Сегодня», «Завтра», будущие даты и «Без даты». Задача со временем переходит в «Просрочено» с наступления срока, в том числе сегодня; задача только с датой — на следующий день.
- Раскрывать выполненные внизу списка; они хранятся до ручного удаления. Одинаковые названия запрещены среди всех задач, включая выполненные.
- При ошибке загрузки повторить чтение и, если исходная строка доступна, аварийно скопировать её. При изменении данных в другой вкладке явно загрузить актуальный список.

Нет аккаунтов, синхронизации, AI, напоминаний, календарного экрана, поиска, импорта и штатного экспорта. Полный объём и исключения — в ТЗ.

## Данные

Задачи хранятся в `localStorage`, ключ `whats-up-bro.storage`, `schemaVersion: 1`. Страница не подключает аналитику, внешние шрифты и API. Сохранение проверяется до показа успешного результата; ошибочные данные не сбрасываются автоматически.

Список отдельный для каждого браузера, профиля, устройства и origin (сочетание протокола, домена и порта). Один HTTPS-адрес не обеспечивает синхронизацию между телефоном и компьютером. Очистка данных сайта удаляет список; резервной копии и восстановления нет. Браузер также может удалить локальные данные по своим правилам, особенно при настройках приватности. Долгосрочная сохранность не подтверждена; для проверки используйте тестовые задачи.

После получения трёх файлов действия работают без Интернета. Повторное открытие HTTPS-сайта офлайн не гарантируется: service worker и PWA отсутствуют.

## Повторение автоматических проверок

Логика: Node.js 22 или новее, без пакетов:

```sh
node --test
node --check prototype/script.js
```

Браузерные проверки: отдельный инструмент разработчика Python + Playwright; приложению они не нужны. Для новой среды установите инструмент и браузеры, если их нет:

```sh
python -m pip install playwright==1.62.0
python -m playwright install --with-deps chromium firefox webkit
```

Команды установки требуют доступа к официальным источникам и, для системных библиотек, соответствующих прав. Не обходите сетевые или браузерные политики. В этой среде уже есть Python Playwright и системный Chromium. Firefox/WebKit не установлены; HTTPS CONNECT к `cdn.playwright.dev` и `playwright.download.prss.microsoft.com` возвращает 403 от прокси. Для их установки потребуется разрешить эти домены в настройках среды, затем повторить установку и прогон. Существующие разрешения сети сохранять.

При работающем статическом сервере в другом терминале:

```sh
python tests/browser_step1.py
python tests/browser_step2.py
python tests/browser_step3.py
```

`BRO_TEST_BASE_URL` задаёт адрес тестирования (по умолчанию локальный HTTP-сервер, порт 8765). `BRO_TEST_CHROMIUM` задаёт исполняемый файл Chromium; по умолчанию `/usr/bin/chromium`. Если используется установленный Playwright Chromium, укажите путь к нему в этой переменной. У шага 2 есть фильтр `BRO_TEST_CASE` по подстроке имени сценария; итоговый прогон выполнен без фильтра.

Шаги 1 и 2 проверяют Chromium. Шаг 3 повторяет основной цикл, перезапуск, очистку данных и работу после загрузки без сети для каждого установленного Chromium/Firefox/WebKit. Отсутствующий движок явно печатается как `NOT RUN`; отсутствие всех браузеров или сбой установленного браузера завершают проверку ошибкой. Такой отчёт не подтверждает Safari на iPhone.

Тесты используют отдельные контексты и временные профили, не пользовательский список. Подмены времени и отказов хранилища существуют только в тестах. Снимки шагов 1/2 сохраняются в системных временных каталогах `whats-up-bro-step1` и `whats-up-bro-step2`. В продукте тестовых переключателей и демонстрационных задач нет.

### Выводы по трём вопросам прототипа

1. **Понятна ли группировка?** Расчёт сроков, порядок и подписи проверены автоматически. Сегодняшние задачи с наступившим временем уходят в верхнее «Просрочено», как требует ТЗ. Понятность этого поведения пользователю ещё не оценена.
2. **Удобен ли быстрый ввод на один день?** Дата сохраняется, время и название очищаются, фокус возвращается в название; Enter и защита от повторной отправки проверены. Личная скорость и удобство, особенно с клавиатурой iPhone, ещё не оценены.
3. **Сохраняются ли задачи между открытиями?** В Chromium на Linux — да, включая полный перезапуск процесса с тем же дисковым профилем и проверку всех сохранённых полей. Windows Chrome/Firefox и настоящий Safari на iPhone ещё не проверены. Вывод о долгосрочной сохранности не делается.

Замеченные особенности: нативный формат полей даты/времени зависит от браузера и ОС; на длинном списке редактирование прокручивает к форме и возвращает к карточке; на 320px действия переносятся на отдельную строку. Проблема видимости кнопки после выхода из редактора исправлена на шаге 2 и проверена повторно. Других воспроизводимых дефектов в доступных прогонах не выявлено.

## Что проверить вручную после размещения

Сначала нужен рабочий HTTPS-адрес с теми же тремя файлами. Затем использовать только тестовые задачи. Эти действия остаются пользователю потому, что у исполнителя сейчас нет целевых устройств; повторять весь локальный набор тестов не требуется.

1. Записать версии Windows/Chrome/Firefox, iOS/Safari и адрес. В обоих браузерах Windows добавить задачу с датой/временем, изменить, выполнить, раскрыть выполненные, вернуть в работу и удалить с отказом, затем подтверждением. Между действиями обновить страницу. Добавить ещё одну задачу, полностью закрыть и снова открыть браузер — она должна сохраниться. Проверить штатный масштаб браузера 200% (AT-34 и оставшаяся часть AT-33).
2. На настоящем iPhone в обычном Safari открыть тот же адрес. Пройти короткий основной цикл, проверить нативные поля даты/времени, экранную клавиатуру, касания и прокрутку длинного списка. Поставить срок через несколько минут, свернуть браузер и вернуться после срока — задача должна перейти в «Просрочено» (AT-35).
3. На iPhone оставить тестовую задачу, закрыть и повторно открыть Safari: задача сохраняется. Затем отдельно очистить данные только этого тестового сайта средствами Safari и открыть его снова: пустой список и пустая форма, старые задачи не восстанавливаются (AT-42). Длительность хранения этой проверкой не устанавливается.
4. При доступной изолированной подмене ошибочных данных на iPhone проверить выделение и ручное копирование readonly-текста при отказе Clipboard API. Не портить рабочие данные ради проверки; при отсутствии инструментов оставить этот аспект AT-35 непроверенным.
5. Оценить читаемость, плотность, положение кнопок, понятность групп и выполненных, быстрый ввод нескольких дел на одну дату и возврат к карточке после редактирования. Это субъективная часть AT-43 и первых двух вопросов прототипа.

После этого результаты целевых платформ и замечания пользователя нужно внести в README и историю `plan.md`. До такого прогона поддержка Windows/iPhone не объявляется проверенной.
